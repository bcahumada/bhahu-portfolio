Informes post-incidente automáticos

«Python calcula, el LLM redacta» · Pydantic · verificación de cifras · Datos sintéticos

Genera un informe post-incidente completo a partir de datos crudos: las cifras se computan en Python, el LLM solo redacta con estructura forzada, y un verificador comprueba que ningún número carezca de respaldo.

Qué resuelve

Los informes escritos íntegramente por un LLM tienden a inventar cifras. Aquí el modelo no calcula nada: recibe métricas ya computadas y las redacta con una estructura fija; luego se valida que cada número exista en la fuente. Es la forma segura de usar un LLM para reporting.

Cómo funciona

  • Python calcula duración, porcentaje de degradación e impacto antes de llamar al modelo.
  • Una clase Pydantic (InformeIncidente) define el esquema; con response_schema el LLM está obligado a llenarlo (resumen, causa raíz, impacto, cronología, acciones, lección).
  • Barrera anti-alucinación (verificar_cifras): cada número del informe debe existir en los datos de origen.
  • Modo dry-run sin API key: imprime las cifras calculadas y el prompt, para depurar sin gastar cuota.

Qué aprendí

El patrón «Python calcula, el LLM redacta» con salida estructurada y verificación programática hace fiable el uso de un LLM para informes. Es el mismo patrón (datos crudos → métricas → informe) que apliqué en trabajo real de análisis de datos.

Evidencia (ejecución del código)

Salida real del script en modo dry-run (sin llamar al modelo). Confirma el patrón: todas las cifras se computan en Python antes de generar el informe.
